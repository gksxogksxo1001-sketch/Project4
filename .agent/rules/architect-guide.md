# 📡 Real-World Info Dashboard: 시스템 아키텍처 설계 지침서 (V2.0)

## 0. 프로젝트 개요 및 지휘관 지침
- **페르소나**: 15년 차 실무 시니어 개발자 (실패 복원력, 데이터 무결성, 투명한 사용자 경험 최우선).
- **목표**: 서버 없는 무로그인 환경(GitHub Pages 등)에서 공개 원천(No-Key, CORS 지원)의 실시간 동적 데이터를 조회하고, **데이터가 안 올 때도 마지막 정상값을 보존(`stale`)하며 실패 유형별로 사용자의 다음 행동을 안내하고, KST 기준 하루 한 줄 기록 및 이틀 변화량 대조를 완벽히 수행하는 회복 탄력적(Resilient) 정보판**을 단일 런타임으로 구현한다.
- **핵심 키워드**: Zero-Backend, No-Key(T04-C11), 5 Failures(T04-C12~C16), Stale Preservation(T04-C17~C18), Recover D2(T04-C19), KST Single Line(T04-C20~C21), 2-Day Delta(T04-C22~C24).

## Phase 2: 카드별 통과 기준 매핑 명세

### 1. 카드 2 — 비밀 없는 호출 (T04-C11)
- **통과 기준**: 브라우저 코드·배포 파일·네트워크 응답·Git 기록에 비밀키 원문이 **0건**.
- **구현**:
  - Open-Meteo 서울 기온(`https://api.open-meteo.com/v1/forecast...`) 및 ExchangeRate-API(`https://open.er-api.com/v6/latest/USD`) 등 No-Key 원천만 사용.
  - 소스코드 및 번들에 `apikey`, `secret`, `token` 등의 비밀값 원문 0건 유지.
  - UI 상에 "비밀값 0건 무인증 공개 호출" 증명 정보 표시.

### 2. 카드 3 — 다섯 가지 실패 & 복구 (T04-C12 ~ T04-C19)
- **합성 실패 5종 및 상태 코드**:
  - `T04-C12` **느린 외부 응답 (Timeout)**: 3초 초과 Abort 타임아웃 발생 -> 실패 상태 표시
  - `T04-C13` **외부 원천 401/403 거절 (Forbidden)**: 권한/접근 불가 오류 -> 실패 상태 표시
  - `T04-C14` **호출 제한 (Rate Limit 429)**: 요청 한도 초과 오류 -> 실패 상태 표시
  - `T04-C15` **오프라인 상태 (Network Offline)**: `Failed to fetch` -> 실패 상태 표시
  - `T04-C16` **응답 형식 변경 (Schema Malformed)**: 응답 JSON 구조 파괴 -> 실패 상태 표시
- **복원력 및 사용자 안내 규칙**:
  - `T04-C17`: 실패 뒤 마지막 정상값(Last Known Good)이 절대 지워지지 않음.
  - `T04-C18`: 실패 뒤 마지막 정상값에 **오래된 값 (`stale`)** 표시가 명확히 붙음.
  - **실패 종류별 설명과 사용자가 취할 다음 행동 다르게 표시**:
    - 401/403: "원천 접근 거절: API 주소 또는 공개 엔드포인트 정책 변경을 확인하세요."
    - 429: "호출 제한: 1분 후 다시 시도하거나 30초 자동 갱신을 잠시 해제하세요."
    - 느린 응답: "응답 지연(타임아웃): 네트워크 대역폭을 점검하고 [다시 시도]를 누르세요."
    - 오프라인: "네트워크 끊김: 브라우저 인터넷 연결 상태를 확인 후 [다시 시도]를 누르세요."
    - 형식 변경: "응답 스키마 변경: 데이터 파서 규격 점검이 필요합니다."
  - `T04-C19`: 실패 상태에서 **[다시 시도 (Retry)]** 버튼 노출 및 **[T04-RECOVER-D2 복구 재생]** 시:
    - 상태가 `fresh`, `error_code`가 `none`으로 즉시 복귀
    - 다음 날짜(D2)의 일별 기록이 정확히 1건 추가됨!

### 3. 카드 4 — 하루 한 줄 (T04-C20, T04-C21)
- **Asia/Seoul KST 날짜 키 기반 Upsert**:
  - `T04-C20`: 기준 시간대(Asia/Seoul)의 **같은 날짜에 여러 번 성공해도 일별 기록은 정확히 1건** 유지 (같은 날짜는 갱신만 발생, 행 수 증가 0).
  - `T04-C21`: 기준 시간대의 **다음 날짜에 성공하면 새 일별 기록**이 생성되어 총 2건으로 증가.
  - UI 상에 "같은 날 재실행 전후 행 수 검증" 도구 탑재 (예: 3회 재실행 후에도 1행 유지 증명).
